## Error

- Compile Error
- Runtime Error
- Logical Error
    
    → 정상 동작 & 정상 종료되었지만 결과가 예상과 다른 경우
    

## Error and Exception

## Error

발생하면 복구할 수 없는 심각한 오류 (ex. 메모리 부족, 스택 오버플로우)

→ 발생하면 그대로 프로그램 종료

## Exception

프로그래머가 적절한 코드를 통해 대비 가능한 오류

→ 예외상황에 맞는 대응 코드 작성

## 예외 처리

- 직접 처리
    
    try, catch, finally 블록으로 처리하는 방식
    
- 간접 처리
    
    throws로 처리를 위임
    

## try ~ catch문

```java
try {
	// 예외 발생이 가능한 코드
} catch (SomeException e) {
	// 예외 발생 처리 코드
} catch (OtherException e) {
	// 다른 예외 발생 시 처리 코드
} finally {
	// 예외 발생이랑 노상관으로 수행되어야 하는 코드
}
```

SomeException이 OtherException보다 더 세부적인 예외여야겠지?
그니까 뒤 블록에 잡는 예외가 더 조상이여야 한다~ 이말이야.

참고로 중간에 return문이 있어도 finally 블록은 수행하고 반환함

## 자동 자원 반납 구문 (try with resources)

```java
try (FileInputStream fis = new FileInputStream("test.txt")){
	// omission
} catch (IOException e) {
	e.printStaceTrace();
}
```

## throws 활용하기

```java
Java
public static void main(String[] args) {
    CheckedThrowsTest et = new CheckedThrowsTest(); // (1) 객체 생성
    try {                                           // (2) 예외 발생 감시 시작
        et.method1();                               // (3) 메서드 호출
    } catch (ClassNotFoundException e) {            // (4) 예외가 여기까지 올라오면 잡음
        System.out.printf("exception handling: %s\n", e.getMessage()); // (5) 예외 메시지 출력
    }
    System.out.println("프로그램 종료");             // (6) 정상 종료 로직
}

public void method1() throws ClassNotFoundException { 
    method2(); 
}

public void method2() throws ClassNotFoundException {
    Class.forName("Some Class"); //여기서 Exception이 터짐
}
```

throws : 내가 직접 예외처리 안하고 나를 호출했던 스택에 예외를 던지겠다
